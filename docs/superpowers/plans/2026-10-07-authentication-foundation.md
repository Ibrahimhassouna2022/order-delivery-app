# Authentication Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Sanctum-protected API identity and role authorization foundations without choosing or building sign-in flows.

**Architecture:** Install Sanctum and API routing, then expose the authenticated user through one protected endpoint. Add an enum-backed user role with a customer default and a small role middleware for later business routes; never accept role changes from user-controlled mass assignment.

**Tech Stack:** PHP 8.4, Laravel Framework 13.35, Laravel Sanctum ^4.0, PHPUnit 12.5, SQLite test database.

**Spec:** `docs/ai-sdlc/specs/SPEC-001.md` (approved; authentication R-01 and security/RBAC R-11).

## Global Constraints

- Use Laravel Sanctum for user authentication (SPEC-001 R-01).
- Enforce role-based access for customers, drivers, and admins (SPEC-001 R-11); restaurant is also a first-release user type (SPEC-001 R-12).
- Do not add Google sign-in, Apple sign-in, guest access, registration/login screens, credential endpoints, or role-assignment workflows in this slice; their design is deferred.
- Add only the approved Laravel Sanctum dependency; do not add another package.
- Do not accept a role from untrusted request input or expose role mutation in this slice.

## Review Focus

- Requests with no credentials must receive an unauthenticated API response; test the protected identity endpoint.
- Malformed bearer tokens must not authenticate; test the protected identity endpoint.
- An authenticated user with a different role must be denied a role-protected route; test the role middleware through a registered test route.
- An invalid role parameter must fail closed rather than grant access or raise an unhandled error; test the role middleware.
- Attempts to mass-assign `admin` to a customer must leave the role unchanged; test the `User` model behavior.
